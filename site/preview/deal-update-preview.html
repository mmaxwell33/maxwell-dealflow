“Your deal was updated” notice

Fires on a pipeline change, queues in Approvals, points at the portal link the client already has.

How it behaves. A pipeline change the client would care about (condition answered, milestone date moved, price, stage) builds one short email and drops it in Approvals. Nothing sends on its own. It reuses the portal link already issued for that deal, so no new token is created and the client has nothing new to log into. If a notice for the same deal is still unsent in Approvals, the next change is merged into it rather than queued as a second email. Corrections (undoing a tick, fixing a typo'd date, snoozes) stay silent, and closing reschedules / closed / fell-through keep their own existing letters. Names and addresses below are made up.
